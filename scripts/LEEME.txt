FarmaGestión — Instalación y primer uso
=======================================

La app trae todo incluido: no hace falta instalar .NET ni ningún otro programa.

CONTENIDO DEL PAQUETE (Windows)
-------------------------------
  FarmaGestion.exe        La aplicación completa.
  Instalar.bat            Copia la app a la PC y crea los accesos directos.
  Desinstalar.bat         Quita la app (conserva los datos).
  appsettings.json        Configuración opcional (ver "Base de datos compartida").
  productos_ejemplo.csv   Ejemplo del formato para importar productos desde Inventario.
  LEEME.txt               Este archivo.

Requisitos: Windows 10 u 11 de 64 bits.

INSTALACIÓN EN WINDOWS
----------------------
1. Extrae TODO el contenido del .zip a una carpeta (no ejecutes nada desde
   dentro del zip).
2. Doble clic en "Instalar.bat".
   - Normal: se instala solo para tu usuario, en
       C:\Users\<tuUsuario>\AppData\Local\Programs\FarmaGestion
   - Clic derecho > "Ejecutar como administrador": se instala para todos los
     usuarios de la PC, en
       C:\Program Files\FarmaGestion
3. Quedan accesos directos "FarmaGestion" en el Escritorio y en el menú Inicio.

Si al abrir la app Windows muestra "Windows protegió tu PC": clic en
"Más información" > "Ejecutar de todas formas". Ocurre porque la app no está
firmada digitalmente; solo pasa la primera vez.

Alternativa sin instalador: copia FarmaGestion.exe (y appsettings.json) a
cualquier carpeta y ábrelo con doble clic.

ACTUALIZAR A UNA VERSIÓN NUEVA
------------------------------
1. Respalda el archivo inventario_medicamentos.db (ver "Datos y respaldo").
2. Cierra FarmaGestión en TODAS las PC.
3. Ejecuta el Instalar.bat del paquete nuevo en cada PC, el mismo día. Los datos y
   el appsettings.json ya configurado se conservan.
   Instala de la MISMA forma que la vez anterior (doble clic, o "Ejecutar como
   administrador"), para que el programa quede en la misma carpeta. Si queda en
   otra, no encuentra el appsettings.json con la base compartida y abre una base
   vacía. La ventana del instalador muestra la carpeta: compárala con la ruta del
   acceso directo (clic derecho > "Abrir la ubicación del archivo").
La primera PC que abra la versión nueva actualiza la base de datos automáticamente.
Una PC con la versión anterior ya no podrá entrar hasta que se actualice (la app
lo avisa con el mensaje "Instala la versión nueva").

NOVEDADES DE LA VERSIÓN 1.1: INVENTARIO POR LOTES
-------------------------------------------------
- Cada producto se controla por lotes: número de lote, vencimiento y existencias
  propias. El stock del producto es la suma de sus lotes.
- Ingresar mercadería (botón verde en Inventario): escanea el código, captura lote,
  vencimiento y cantidad. Si el lote ya existe se suman las unidades; si no, se crea.
  El lote y la fecha son obligatorios.
- Registrar producto: solo datos del producto; opcionalmente su primer lote.
  Editar producto ya no cambia existencias: eso se hace por lotes.
- En la tabla de Inventario, al seleccionar un producto se despliegan sus lotes con
  su estado (vigente, por vencer en 90 días, vencido). El botón "Dar de baja" deja
  un lote en cero (vencido, dañado, etc.).
- Despacho: la cajera escanea igual. El sistema descuenta primero del lote que vence
  antes (FEFO). Los lotes vencidos no se usan mientras haya vigentes; si se usan, la
  app advierte pero no bloquea la venta.
- Al actualizar desde la 1.0, cada producto con existencias queda con un solo lote
  (su lote y vencimiento anteriores, o "INICIAL" si no tenía lote). Si algún lote
  quedó con número o fecha equivocados, corrígelo con "Editar" en la fila del lote.
- Dar de baja pide la cantidad y el motivo (vencido, dañado, pérdida, ajuste, otro) y
  deja registro de quién lo hizo. Se puede hacer desde Inventario o desde Reportes.
- Reportes muestra "Vencimientos de lotes": vencidos y los que vencen en 30, 60 o 90
  días, con botón para darlos de baja, y la lista de las últimas bajas.
- En Despacho, si un producto tiene más de un lote, aparece un selector para elegir
  de cuál sale (por defecto, el que vence antes). El comprobante imprime el lote de
  cada línea.

NOVEDADES DE LA VERSIÓN 1.2: DESHACER DESPACHO Y REPORTES
--------------------------------------------------------
- Deshacer despacho: una venta mal hecha se anula y las unidades vuelven a los
  mismos lotes de los que salieron. Se puede hacer desde el comprobante, al
  confirmar la venta, o desde Reportes con el botón "Deshacer" de cada fila.
- Pide un motivo obligatorio y deja registro de quién la anuló y cuándo. El
  despacho no se borra: queda marcado como "Anulado".
- Quién puede deshacer: un usuario Empleado solo las ventas del día; el Admin,
  ventas de cualquier día. No se puede deshacer dos veces la misma venta.
- Las ventas hechas antes de la versión 1.1 no guardaban el lote de cada unidad y
  no se pueden deshacer automáticamente. Si hace falta, devuelve las unidades con
  "Ingresar mercadería".
- Reportes: las ventas anuladas se ven atenuadas, con el total tachado, y no suman
  en ventas totales, despachos, ticket promedio, unidades ni en el gráfico.
- Reportes: cada despacho muestra los productos que llevó (los tres primeros y
  "+N más") y tiene un botón "Ver" que abre su comprobante para descargarlo en PDF
  o volver a imprimirlo.
- El comprobante y su PDF de una venta anulada llevan la marca "ANULADO" con la
  fecha, el usuario y el motivo.
- Si vienes de la versión 1.0, esta actualización incluye también todo lo de la
  1.1 (inventario por lotes, ver arriba).

DESINSTALAR
-----------
Ejecuta "Desinstalar.bat" (como administrador si se instaló para todos los
usuarios). Los datos NO se borran; si ya no los necesitas, elimina a mano la
carpeta de datos indicada abajo.

PRIMER INICIO DE SESIÓN
-----------------------
Al abrirla por primera vez se crea la base de datos y un usuario administrador
con una contraseña ALEATORIA, guardada en un archivo de texto:

  - Windows:  C:\Users\<tuUsuario>\AppData\Roaming\FarmaGestion\credenciales_admin.txt
  - macOS:    ~/Library/Application Support/FarmaGestion/credenciales_admin.txt

Usuario: admin
Contraseña: (la que aparece en ese archivo)

IMPORTANTE: entra, crea tus usuarios, cambia la contraseña del admin y borra
ese archivo de credenciales.

DATOS Y RESPALDO
----------------
Toda la información se guarda localmente en esa misma carpeta:

  - inventario_medicamentos.db   la base de datos (respáldala copiando el archivo)
  - farmagestion.log             registro de errores, útil para soporte

Por defecto cada equipo (y cada usuario de Windows) tiene su propia base de datos.

BASE DE DATOS COMPARTIDA (opcional)
-----------------------------------
Para que varias PC trabajen sobre el mismo inventario, coloca la base de datos
en una carpeta compartida de la red y, en cada PC, edita el appsettings.json
que está junto a FarmaGestion.exe:

  "ConnectionStrings": {
    "Inventario": "Data Source=\\\\SERVIDOR\\Farmacia\\inventario_medicamentos.db"
  }

(En JSON cada barra invertida se escribe doble.) Todas las PC deben tener
permiso de lectura y escritura sobre esa carpeta. La app ya está preparada para
este modo: espera hasta 30 s si otra PC tiene la base ocupada.

IMPORTAR PRODUCTOS POR CSV
--------------------------
Desde Inventario > Importar CSV. Formato (ver productos_ejemplo.csv):

  Codigo,Nombre,Precio,Existencias,Lote,Vencimiento

La primera fila es el encabezado. Cada fila es un ingreso de lote: Existencias es
la cantidad que entra de ese lote. Lote y Vencimiento son obligatorios; la fecha
va como AAAA-MM-DD. No uses comas dentro del nombre. Si el código ya existe, se
actualiza el precio; si el lote ya existe, se le suman las unidades; si es otro
lote, se crea. Las filas incompletas se rechazan y se muestran al final.

macOS
-----
1. Copia "FarmaGestion.app" a la carpeta Aplicaciones.
2. La PRIMERA vez: clic derecho sobre la app > "Abrir" > "Abrir".
   (Es necesario solo la primera vez porque la app no está firmada con Apple Developer.)
